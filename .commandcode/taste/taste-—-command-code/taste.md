# Taste — Command Code
- Prefers direct PostgreSQL access via a connection string (plain SQL/pg client) over an ORM such as Prisma ("dont use prisma orm just direct postgre with connection string"). Confidence: 0.85
- Prefers the simplest reliable solution that meets requirements over enterprise-level architecture: rejects outbox-style designs, microservices, Redis/message brokers, and other unnecessary complexity ("stop expanding the architecture with unnecessary enterprise-level complexity"). Confidence: 0.8
- Prefers a thorough audit/plan first and an explicit approval gate before any implementation starts ("do not start implementation yet", "wait for approval before making any code changes"). Confidence: 0.75
- Prefers work delivered incrementally in explicitly scoped phases: implement one phase, then report changed files, completed functionality, test commands, and blockers, and wait for approval before the next phase. Confidence: 0.75
- Requires every claim of verification to be backed by a command actually run: don't report tests as passed, and don't say something works, unless it was executed and observed. Confidence: 0.7
- Wants existing, working code left untouched when adding new functionality: prefer additive new files and only the necessary minimal edits, and don't refactor or redesign unrelated components or the existing UI ("do not modify, delete, refactor, or redesign any existing frontend components", "do not change unrelated frontend components"). Confidence: 0.75
- When explaining how to try or demo a feature, frame it in terms of the client-facing frontend flow (which page to open, what to click, what appears in the browser), not DB queries or raw API calls — "client ko frontend hi dekhna hota". Confidence: 0.65
- Prefers brief, condensed explanations — asks for repeated shortening ("thora short", "thora or short batoa") rather than long multi-section breakdowns, especially for client-facing summaries. Confidence: 0.6
- Wants architecture plans to explicitly separate confirmed requirements, technical implementation decisions, client decisions still required, and security/operational risks rather than mixing them. Confidence: 0.6
